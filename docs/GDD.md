## 1. 願景與範圍

### 1.1 願景

重現 2001 年《金庸群俠傳 Online》剛開服時的浪漫：

- 沒有角色等級。成長靠**實戰經驗**和**學習點數**，學點要一點一點「消」進每一門武功。
- 一個人拜入門派，守門規、學武功、練到出師。
- 踩地雷遇敵，進入**半即時（ATB 時間棒）格子戰鬥**。
- 善惡、殺氣、PK值、懸賞、死亡掉屍，讓江湖有真實的代價。
- 和三五好友組隊，排陣形、闖銅人陣，在同一個自架的江湖裡生活。

### 1.2 「1.0」的定義與版本線

**範圍決定（擁有者確認）**：本作**不限於 1.0**。以經典 1.0 的核心循環為基礎，原作同一條產品線的**後續官方資料片**依序排成之後的里程碑。如果不同版本的規則互相衝突，就做成每個世界各自的伺服器選項。

「1.0」本身怎麼定義，兩份研究的證據份量相當：

- **說法一**：jy2001 年表把「神鵰大俠」（2001-09-28）列為第一個資料片，內容是新增丐幫、京城、絕情谷。
- **說法二**：17173 的〈決戰光明頂〉頁面要求玩家先安裝「原版金庸群俠傳 Online **神鵰大俠**」。照這個說法，「神鵰大俠」是零售客戶端的名稱，也就是 1.0 本身，第一個真正的資料片是決戰光明頂。

兩種說法都有直接文字證據【待考證：哪一種才準確】。不過它們對「神鵰期屬於 1.0」的結論一致，差別只在開服當天（1.0-A）有沒有一個獨立的版本名稱。範圍擴大之後，這個問題不影響開發排程。

### 1.4 里程碑摘要（詳見第 13 章）

- **M0 專案骨架**：Godot 與 GodotSteam 的技術打底。
- **M1 單機核心循環**：西夏、大理兩城和兩城之間連續的野外（照原作走路、踩地雷，見 7.1）；少林、華山的山門從西夏走東路到得了；驛站只辦送信；ATB 戰鬥、學武、死亡。
- **M2 Steam 合作連線與 PK**：2–8 人同一個江湖。M1 加 M2 就是 MVP。

## 2. 角色創建與屬性

### 2.1 創建流程

1. 選性別。性別會影響可以加入哪些門派，見第 3 章。
2. 擲骰決定 7 項屬性。可以無限重擲。單項擲骰上限 25【已證實：悟性；其他屬性是否一樣【待考證】，預設全部套用 25】。
3. 分配 5 點自由點數，可以讓單項超過 25，例如悟性 25+5=30【已證實】。
4. 設定生日（月份）。之後每次生日會隨機提升屬性【已證實】，數值【待考證】。
5. 選出生城市：1.0-A 只能選**西夏**或**大理**【已證實】，1.0-B 加入**京城**；揚州在 M7（勇闖俠客島）開放【後期版】。預設世界（只開 1.0A）沒有京城；開了 1.0B 才有京城，京城也不能當 M1 的出生城【設計提案】。
6. 初始物品：精藥水 ×5【已證實 ZOL 2006；**M3c 註（M3C_PLAN §1.4 F3）**：這份是 ZOL 2006 的清單，2001-06-30 官方新手清單是 9 種工具＋傳家寶刀／寶甲／寶鞋＋稻米種子、活力頌、清水、熟牛肉、地圖，0 錢；M3c 只建傳家三件資料列、預設不換（開放問題 Q1）】、少量銀兩、布衣。「傳家寶刀」作為初始裝備這點**查無來源**【待考證】，預設不給，改給木刀。

**學點取得公式**【設計提案，依據已證實的「實戰越少，每場賺到的學點越多」】

```
學點 = 怪物基礎學點 × clamp( (怪物強度實戰值 + 1000) / (玩家實戰 + 1000), 0.2, 3.0 ) × 隊伍分享係數
實戰 = 怪物基礎實戰 × clamp( 同上比例, 0.1, 2.0 )
隊伍分享係數 = 1 / 參戰人數^0.5 （參戰者全員都能拿，鼓勵組隊）
```

> **少林「消實戰」**：17173 記載「實戰少，賺到的學習點數多（所以之前在少林可消實戰的功能已經被改掉了）」【已證實】。也就是說，開服初期少林曾經可以把實戰經驗消掉，換取更高的學點收益，後來被移除。本作**不做**這個功能，因為上面的公式會讓它變成刷學點的漏洞；只在少林 NPC 的對話裡提一句，當作懷舊彩蛋。

## 3. 門派

### 3.1 通則

- **門派總數**：1.0 收費版共 11 派【已證實】。1.0-A 有 10 派（不含丐幫）【待考證：推論】。
- **門派技能**：每派有 1 項門派技能，決定戰鬥中的觸發效果；官方表的「會耗精與內力／精與神」是**每次觸發**的消耗【已證實：官方 index_jy2-25】，觸發本身 2002-01-25（決戰光明頂）才開【已證實：news 399】，2001 年門派技能只用來限制學武。學習方式各派不同（武當俠義只靠任務、恆山禪悟扣神、血刀恐嚇耗精神…，研究 M3a 章）；本作向師父消點的額外消耗寫在 sects.sect_skill_train_cost【設計提案】（M3a 審查修正：原本把觸發消耗當學習消耗）。限制本門武功等級：少林佛法、丐幫乞討【已證實】；其他 9 派套用同規則為【設計提案】。
- **出生城市與門派的對應**：出自懷舊版（jyhj，2008 以後）指南【後期版：懷舊版；是否與 2001 年相同【待考證】】，本作採用：
  - 西夏 → 靈鷲、星宿
  - 大理 → 血刀、峨嵋、全真、古墓
  - 京城 → 少林、武當、丐幫、華山、恆山（懷舊版的分法）。1.0-A 沒有京城，這些山門在原作座標上是西夏東南方的一串山（恆山、華山、少林、武當），本作從西夏走東路連過去（見 7.1）【擁有者決定：照原作地理】。
- **門規與坐牢**：違反門規坐牢 1 天（**以遊戲時間計，即累計上線時間**）。規則【已證實】，但出處是 2004 年的官方門規頁；17173 DIAO 把監獄列為神鵰期新增，所以 **1.0-A 有沒有坐牢【待考證】**。本作預設 1.0-A 也有坐牢（關在各派思過處）。開關是 `rule_profile.jail_enabled`（TECH_ARCH 5.6），作用於**所有 era**：設為 false 時任何時期都沒有坐牢，違規一律改成「禁止學武」（`friends_casual` 預設組合就是 false）。1 遊戲日 = 2 小時累計上線時間【設計提案】。
- **叛派**：
  - 2001 年來源：武功減半、成為該派叛徒、永遠不能回該派【已證實】。
  - 後期官方頁（2004）：連基本武功也減半，門派技能歸零，成為公敵；被抓到坐牢 3 天【後期版】。喬峰傳奇以後，叛派還會清除畢業記錄（M9）【後期版】。
  - **本作預設**：特殊武功全部減半，門派技能歸零，成為叛徒，永遠不能回派；**基本武功不減**。「基本也減半」做成 `rule_profile.betrayal_halves_basics`（TECH_ARCH 5.6）。
  - 加入後馬上離開的人，武功只有 1 級，所以不受影響【已證實】。
- **開除**：等同叛教。例如少林被開除，本門武功減半，永遠不能再入少林【已證實】。
- **執法者**：華山、恆山沒有執法者（因為外人進不了山門）；血刀、星宿、丐幫、靈鷲也沒有【已證實】（出處同為 2004 年後的官方門規頁；1.0-A 是否相同【待考證】）。
- **同時只能屬於一個門派。**

### 5.2 戰鬥場景

- 遇敵後**切換到獨立的戰鬥畫面**【已證實】。
- 戰場是格子地圖，本作採用 12×8【設計提案】。

### 5.3 時間棒公式【設計提案】

```
每 tick (0.1 秒) 時間棒增加 = 4 + 機敏 × 0.15 + 基本身法 × 0.03 + 門派輕功 × 0.02
時間棒滿值 = 100
負重 > 80% 時增加量 × 0.7；凍傷狀態 × 0.5
```

- 機敏 20、身法 0 的新手：約 7/tick，1.4 秒一動。
- 機敏 30、身法 100 的高手：約 13.5/tick，0.74 秒一動。

**等待模式**（伺服器選項，預設開啟）：有玩家正在選指令時，**所有時間棒暫停**，對應巴哈回顧文所說的「回合制戰棋式」手感。關閉這個選項就是純半即時。這樣可以照顧連線延遲和文字閱讀時間。

### 5.5 成數機制

原作有「刀攻擊加劍一成、拆招卸力減一成」「掌比劍少一成、拆招卸力多一成」，還有「基本劍法 120 時 1 成和 10 成沒有差別」的記載【已證實但語意不明，待考證】。

本作解讀：「成」是**出力程度**。

```
出力係數 = 0.55 + 0.05 × 成數                # 1成=0.6, 10成=1.05
內力消耗 = 招式內力 × 成數 / 5
基本武學精熟補正：若 對應基本武學 ≥ 120，出力係數固定 1.05 (高手不必全力即可發揮全威)
```

兵器類別修正（以劍為基準）：

| 類別 | 攻擊 | 對手拆招卸力效果 |
|---|---|---|
| 刀 | +10% | −10% |
| 劍 | 0 | 0 |
| 拳掌 | −10% | +10% |
| 棍、杖、鞭、槍 | 0 | 0（【待考證】） |

### 5.6 傷害公式【設計提案】

```
攻擊力 = 武器強度 + 臂力 × 1.5 + 招式威力 × (1 + 武功等級 / 60) + 對應基本武學 / 4
攻擊力 ×= 出力係數 × 兵器類別修正 × (1 + 殺氣 / 10000)
防禦力 = 防具強度 + 根骨 × 1.2 + 拆招卸力 / 3 × 對手兵器拆招修正
防禦力 ×= (1 − 膽識 × 0.004) × (1 − 殺氣 / 20000) × (按「防」時 1.5 + 基本內功/400)

命中率 = clamp(80 + (攻方武功等級 − 守方閃躲縱躍) × 0.3 + (攻方機敏 − 守方機敏) × 0.8, 10, 95) %
爆擊率 = 2 + 膽識 × 0.3 %
爆擊倍率 = 1.5 + 根骨 × 0.01
浮動 = 隨機 [1 − (0.3 − 定力×0.006), 1.1]     # 定力越高越穩定
內功隨機加成 = 隨機 [0, 基本內功 / 10]          # 對應官方「內功提供隨機攻防加成」

傷害 = max(1, (攻擊力 − 防禦力 × 0.6) × 浮動 + 內功隨機加成)  → 扣「氣」
反擊率 = 定力 × 0.4 %（定力 ≥ 25 才生效；慈悲另外判定）
```

**校準目標**：

- 新手（實戰 0，木刀）打野兔約 8–15 點；新手怪物的氣 < 400【已證實的新手建議】。
- 實戰約 1 萬的玩家適合鬼王洞；高昌機關人無論如何每下都打 200+【已證實】。

### 5.10 查看偵察【設計提案・非原作】（擁有者核准的 M3 小範圍，2026-10-19）

原作的踩地雷只在**走進房間**時判定，練功時得在兩個房間之間來回走。擁有者回報這對朋友小團體太磨人，核准加一條路：

  只要表不是空的就**必定發現**；怪物種類與數量規則與踩地雷相同（權重、`count [lo, hi]`、最多 4 隻），不受守護者之煙影響。
- **提示**：視窗「你發現附近有：野兔 ×2」（怪物立繪、倒數），按鈕「迎戰」（Enter）與「離開」（Esc／⊠）。
  迎戰＝與踩地雷完全相同的開戰（`ENCOUNTER`：同房、閒置的隊友一起被拉進來，獎勵、死亡規則都一樣）；離開就關掉，什麼都不發生。
- **主機權威**：提示存在主機的 session（id、角色、房間、怪物、到期時間），30 真實秒有效；換房、進戰鬥、離線／換角、過期、主機關掉選項都會失效。
  迎戰時主機驗證 id、同一個房間、不在戰鬥中、氣 > 0；客戶端只回傳 offer id，不能指定怪物。
- **冷卻**：在能偵察的房間偵察一次後 6 秒（世界時間，與修煉內力一樣隨時間倍率縮放；×2 時真實 3 秒）不能再偵察，按鈕顯示「查看（5 秒）」並灰掉；
  安全的房間（沒有遇敵表）查看沒有冷卻，只印房間描述。
- **伺服器選項** `scout_enabled`（預設開；主機可在「伺服器設定」切換）：關掉時「查看」與以前完全一樣。
- 數值（6 秒冷卻、30 秒有效）都是【設計提案】；原作沒有這個功能。

## 6. PK 與善惡

### 6.1 善惡度

- 範圍 −1000 到 +1000【已證實】。
- 殺死善方 NPC 會降低善惡，殺死惡方 NPC 會提高善惡【已證實：規則存在；數值為提案 ±5 / ±3】。
- **名字顏色**【已證實】：惡人藍色、中立黃色、善人白色。分界提案：善惡 < −100 為惡，> +100 為善。
- **敵對效果**【已證實】：
  - 善惡為負的玩家，進出城時會被守衛攻擊。
  - 善惡為正的玩家，和葉二娘說話或進入血刀門時會被攻擊。
  - **善惡為負的玩家，可以在峨嵋（善惡為負）、全真（≤ −500）、武當（≤ −1000）被該派弟子主動攻擊，當作練功點**。
- 調戲紡織娘會扣善惡（−100 這個數值【待考證】）。
- 強制殺死非惡人的玩家：善惡 −10；殺死惡人：+10【設計提案】（M2_PLAN 5.2）。數值刻意取小：善惡為負進出城就有守衛【已證實】，太大的扣分會讓「PK值 > 3 才追殺」的寬限失去意義。

### 6.2 PK 流程

| 方式 | 規則 | 依據 |

| 叫戰 | 雙方都在視線範圍內，對方同意才開戰；系統選單可以關閉「接受叫戰」 | 【已證實】 |
| 強制 PK | 按住「連結鍵」點擊對方即可開戰。按鍵可自訂，預設 Ctrl | 【已證實】 |
| PK值 | 每強制殺死 1 名玩家 +1（屬於惡意 PK）；每真實 30 分鐘 −1 | 【已證實 newton】；本作只在上線時計時【設計提案】 |
| 被強制 PK 時反殺 | 只有按連結鍵出手的人算惡意 PK；被出手的一方殺死出手者算自衛，照叫戰擊殺算（PK值、善惡不變，殺氣照加，不全服廣播） | 【設計提案】（原作把 PK值 +1 綁在「按連結鍵強迫開啟戰鬥」的人，M2_PLAN 5.2） |

### 6.3 殺氣

- 殺怪和殺人都會累積殺氣【設計提案：殺人 +100，殺惡方 NPC +5】。
- 殺氣提高攻擊、降低防禦【已證實】。
- 殺氣 > 2000 會被少林開除【已證實】；混元掌要求殺氣為 0【已證實：qqnjy 至尊版】【後期版】。
- **實作狀態（2026-10-18）**：M2 起殺氣與 PK值都是真的數值，但門規（受戒、開除：PK值、殺氣、善惡、殘殺同門）要到 M3 才做（M2_PLAN 2.2）。M2 期間少林弟子殺氣破 2000 或強制 PK 同門都**不會**被受戒或開除。

### 6.4 死亡懲罰

兩組死亡規則屬於**不同年代**，並不互相矛盾：

| 項目 | 2001 規則（17173 yinan/28–29）【已證實】 | 後期規則（官方死亡頁、newton；約 2004 年以後）【後期版】 |
|---|---|---|
| 武功 | **全部**武功降 1 級 | 實戰 ≤ 500 不受影響；否則只有最高的一項特殊武功降 1 級，基本武學不受影響 |
| 物品 | **全部物品**留在屍體上 | 全身**裝備**掉在屍骨處（背包是否掉落沒有寫） |
| 拾回期限 | 屍體保留 **30 分鐘**：前 10 分鐘只有本人和他指定的人能撿，之後 20 分鐘任何人都能撿 | 本人或授權者只有 **10 分鐘**可以撿回；之後開放給任何人（屍體何時消失沒有寫） |
| 重生 | 最後一次設定的記錄點（查小鏞）；沒有記錄點就回出生地 | 同左 |
| PvP | 神兵利器自動轉到擊殺者身上 | 同左 |

> 兩份研究的分歧在於：一份讀 17173 yinan/29 得出 30 分鐘；另一份讀後期官方頁與 newton，只找到 10 分鐘，因此建議刪掉 30 分鐘。兩者其實分別是 **2001 規則（30 分鐘，其中前 10 分鐘受保護）** 與 **後期規則（10 分鐘保護後開放）**。

**規則預設組合（rule_profile preset）**（四選一，見 TECH_ARCH 5.6 的 `rule_profiles.json`）：

1. **2001 嚴苛** = `classic_strict`（`death_rule = STRICT_2001` + `corpse_window = CLASSIC_30`）：完全照 2001 規則（全部武功降 1 級、全部物品掉落、30 分鐘屍體）。
2. **後期官方** = `later_official`（`STANDARD` + `LATER_10`）：完全照後期規則（只降最高特殊武功、只掉裝備、10 分鐘保護後開放）。屍體何時消失原作沒寫，本作暫用 30 分鐘【設計提案】，所以**目前屍體時間和懷舊標準一樣**（M2_PLAN D6；伺服器設定面板會這樣寫）。
3. **懷舊標準（預設）** = `classic_standard`（`STANDARD` + `CLASSIC_30`）：**混合規則**【設計提案】。武功與物品採後期規則（只降最高特殊武功、實戰 ≤ 500 不受影響、只掉裝備），屍體時限採 2001 年的 30 分鐘（10 分鐘保護 + 20 分鐘公開），讓好友有時間趕來救援。注意：這個組合在原作任何時期都不存在。
4. **好友休閒** = `friends_casual`（`death_rule = CASUAL`）：不降級，只掉金錢的 10%【設計提案】。

規則開關本身：`death_rule` 只有三種值（`STRICT_2001`／`STANDARD`／`CASUAL`）；屍體時限 `corpse_window` 是 `CLASSIC_30`／`LATER_10`。兩者都可以在預設組合之上用 `rule_profile.overrides` 個別覆寫，自由搭配。

其他規則：

- 「屍體漂浮」開關和「授權撿取」選項都會做【已證實】。授權撿取 M2 已做；「屍體漂浮」只確認開關存在、原作沒寫它做什麼，延到查到說明後（M2_PLAN 2.2）。
- Alt+F4 逃避戰鬥的漏洞：斷線的角色留在戰場、由 AI 自動「防」**直到戰鬥結束**（照樣分勝負、照死亡規則受罰）；戰場上已沒有在線玩家時當場快轉到分出勝負。同一角色在戰鬥結束前重新連線，會**接回原來那場戰鬥**【設計提案】（M2_PLAN 偏差 D4；原本寫的「留 30 秒後移除」已不用）。

## 12. 多人模式

### 12.1 技術棧

| 項目 | 選擇 |
|---|---|
| 引擎 | Godot 4.6.3 標準版。**用 godotengine.org 下載的獨立編輯器**，不要用 Steam 版編輯器，可避開 steam_api64.dll 版本過舊的問題 |
| Steam | GodotSteam GDExtension **4.23**。4.23.1 被標為不穩定，暫時不用。從 Codeberg 或 Godot Asset Store 下載（GitHub 已封存，檔案日後會移除）。授權目前是 MIT，每次升級都要重新檢查 |
| 網路 | GodotSteam 內建的 `SteamMultiplayerPeer`（4.17 以後才有），搭配 Godot 高階 RPC。**不要**同時安裝 ExpressoBits 的 steam-multiplayer-peer，兩者類別註冊會衝突 |
| 傳輸抽象 | 由 Autoload `NetworkManager` 選擇並建立傳輸層，共三種：Steam、ENet（區網測試或沒有 Steam 時）、Offline（單機，peer id 1）。切換的方式是換掉 `multiplayer.multiplayer_peer`，`WorldServer`／`ClientState` 的 RPC 程式碼不用改（見 TECH_ARCH 4.2） |
| 資料 | 所有內容資料表都是 JSON，放在 `res://data/*.json`（見 TECH_ARCH 第 5 章）。JSON 不會被 Godot 當成翻譯檔匯入，所以沒有 CSV 的 Keep File 陷阱。企劃若想用試算表，可在 `design_tables/`（不在 `res://` 內）編輯 TSV，再用 `tools/tsv2json` 轉檔 |
| AppID | 開發期用 480（Spacewar）；上架前付 Steam Direct 費用（100 美元），申請正式 AppID |

### 12.2 Steam 初始化

- 在 Autoload `SteamManager` 裡手動呼叫 `Steam.steamInitEx(480, false)`。Project Settings 的 initialize on startup 與 embed callbacks 都要關閉（見 TECH_ARCH 2.1）；兩種初始化方式只能選一種，否則會初始化兩次。回傳的 `status == 0` 才算成功：
  - 1 = 其他失敗
  - 2 = Steam 沒有開
  - 3 = 客戶端過舊
- 每一幀都要呼叫 `Steam.run_callbacks()`。這個 Autoload 的 `process_mode` 必須設為 `ALWAYS`，暫停時回呼才不會停。
- 初始化失敗時退回 ENet 或 Offline，並在畫面上顯示原因。

### 12.3 開房與加入

- 開房：
  1. 呼叫 `Steam.createLobby(LOBBY_TYPE_FRIENDS_ONLY, 8)`。
  2. 收到 `lobby_created(result == 1)` 後，用 `setLobbyData` 設定 `game=jymini_v1`、`proto=<Protocol.VERSION>`、`name=<顯示名>`（見 TECH_ARCH 13.1）。
  3. 呼叫 `peer.create_host(0)`（不使用 host_with_lobby，見 TECH_ARCH 17 #10）；客戶端用 `create_client(host_steam_id, 0)`。
- **480 的雜訊**：AppID 480 上有大量別人的測試大廳。搜尋時一律加上 `addRequestLobbyListStringFilter("game","jymini_v1",LOBBY_COMPARISON_EQUAL)`。
- 邀請：呼叫 `activateGameOverlayInviteDialog(lobby_id)`。
- 加入：監聽 `join_requested`；冷啟動時讀取啟動參數 `+connect_lobby <id>`。
- **480 的已知限制**：
  - 冷啟動時接受邀請，可能會啟動 Spacewar 而不是本作【待考證，需要兩個帳號實測】。在那之前，請好友**先開遊戲，再接受邀請**。
  - Vulkan 下 Steam 覆蓋介面不穩定，請從 Steam 用戶端啟動來測試。
  - 成就和統計數據是所有 480 開發者共用的，所以開發期不做。
- **踢人**：GodotSteam 教學引用 Spacewar 的做法，由主機發訊息踢人；「Steam 大廳沒有原生踢人功能」是由此推論【待考證】。本作做法：由主機發出 RPC 要求對方斷線，同時主機端關閉該 peer（`disconnect_peer` 是否有實作也【待考證】）。
- `server_relay`：設在 `multiplayer.server_relay`（SceneMultiplayer）。主機權威架構下所有訊息本來就經過主機，這個值影響不大。

### 12.4 主機權威模型

- **主機（peer 1）**：
  - 負責世界模擬、戰鬥結算、隨機數、經濟、存檔。
  - 客戶端只送 intent：`WorldServer.c2s_intent(seq, kind, args)`，kind 例如 `move`、`battle_cmd`、`learn`（TECH_ARCH 6.3）。
  - 主機驗證後套用，再把結果廣播出去。
- **同步頻率**：
  - 世界只同步場景層級的狀態（誰在哪一格）。
  - 戰鬥時間棒以事件錨點（`battle_gauges`）同步，另有 1 Hz 校正（`s2c_battle_tick`，TECH_ARCH 10.6）。
  - 文字事件以可靠 RPC `s2c_events` 批次傳送。
- **防作弊**：好友環境以防止誤操作為主，所有數值計算都只在主機端進行。

### 12.5 存檔與持久化

| 存檔 | 位置 | 內容 |
|---|---|---|
| 世界存檔 | 主機的 `user://worlds/<world_id>/world.json`（＋`options.json`、`bak1`–`bak5`） | 世界狀態、NPC、屍體、信件、組織 |
| 角色檔 | 同上，`characters/<identity>/<char_id>.json`；identity = `steam_<SteamID64>` 或 `local_<uuid>`（ENet／單機沒有 SteamID 時用後者） | 每個 identity 在同一世界最多 3 個角色（TECH_ARCH 8.1） |

- 主機每 60 秒自動存檔一次，對應原作的即時自動存檔。另外在玩家離線時和關服時也會存檔。
- **角色護照**【設計提案】：
  - 玩家離開時，主機把該角色的檔案和雜湊值傳給客戶端，存成本地備份。
  - 用途一：主機失去資料時可以恢復。
  - 用途二：帶到別人的世界去玩。伺服器選項「允許外來角色」預設關閉，因為不同世界的數值可能不一致。

### 12.6 主機離線時

原作是 24 小時常駐的伺服器，本作做不到。伺服器選項 `host_offline_policy` 有三種（TECH_ARCH 8.6）：`FROZEN`（預設，下面第 1 項）、`BACKUP_HOST`（第 2 項，M2）、`DEDICATED`（第 3 項，M4 選用）。

1. **世界凍結**：主機關閉時，整個江湖暫停。時間制的機制（PK值遞減、坐牢、腐壞）一律以**累計上線時間**或**世界運行時間**計算，所以不會因為主機離線而吃虧。原作的坐牢本來就以上線時間計，正好吻合。
2. **主機轉移（手動）**：
   - 主機定期把世界快照同步給一位「副主機」好友（選項）。
   - 主機長期離線時，副主機可以用最新快照開服。
   - 快照帶有版本號；原主機回來時，由玩家選擇以哪一份為準。
3. 不做自動主機遷移，也不用 Godot server 匯出或 GameServer API（GodotSteam 的 server 版沒有 MultiplayerPeer）。**M4 選用**：一般版 GodotSteam 加 `--headless --dedicated` 的無介面專用主機（`host_offline_policy = DEDICATED`，見 TECH_ARCH 8.6），讓一台常開的電腦跑世界，主機本身不是玩家。
4. **單機模式**：OfflineTransport 下也能進入同一個世界自己練功，但要先取得世界擁有者的同意。這對應原作「偏單機網遊」的需求。

### 12.7 跨版本相容

- 世界存檔包含 `schema_version`，以及內容資料表的雜湊。
- 加入時檢查雙方的遊戲版本和內容雜湊，不一致就拒絕加入並提示更新。
